# Week 4 — Objects, tests, and something to show people

> **Destination**
> Model a thing as an object, prove your code works with tests you wrote yourself, and
> publish a repository a stranger can clone and run.

This is the last week of pure Python and the first week you produce something for an
audience. By Friday you have **Project 1** on GitHub — the first of the three that get
you interviewed.

---

## Wednesday is the unusual one

Every Wednesday so far, tests were something that happened *to* you. This week you
write them, and **your tests get tested**: your suite is run against deliberately
broken versions of the code, and it has to catch every one.

A test suite that passes on broken code is worse than no tests, because it produces
confidence with nothing behind it. Finding out which of your tests are real is a skill
almost nobody has, and it comes up in interviews constantly.

---

## Project 1

The week-3 expense tracker, rebuilt around classes, with your own test suite and a
README. It is small. That is fine — what a hiring manager reads is whether it is
**finished**: tests that run, a README that works, commits that tell a story.

Half-finished ambitious projects lose to small complete ones every time.

---

## And your first mock interview

Friday's defence ends with a 30-minute recorded mock, gate-1 format. It will go badly.
It is supposed to — that recording is the baseline you get played back against in week
12, and the difference between those two tapes is where your confidence will actually
come from.
